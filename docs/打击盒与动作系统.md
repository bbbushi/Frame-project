# 打击盒与动作系统 — 设计与工作逻辑

> 代码：`Assets/ActionSystem/`（Hitboxes/Hitbox·HitboxMelee·HitboxExplosion·HitboxBullet、HitBoxConfig、Damage、Damagable、Displacement、ActionIgnoreMask）
> 定位：攻击侧判定 + 打击反馈 + 行为锁——"打击感三要素（位移/顿帧/屏震）"的实现层。
> 前置阅读：《实体与组件模型》（FixedFrameInterval、刷新链）

---

## 一、设计思路（为什么这么设计）

**1. Hitbox = "一次攻击判定的临时 GameObject"，模板方法模式。**
基类定骨架：`FixedUpdate → CollideCheck() → HitResultCheck(hitTargets)`（Hitbox.cs:81-95），两步默认空实现，子类按攻击形态（近战/爆炸/弹丸）各自覆写检测与结算；命中结算 `Hit()` 与反馈 `PlayHitEffect` 在基类复用。新攻击形态 = 新子类，主干不动。

**2. 数据与形态分离：Config 只装手感，几何归 prefab，伤害外部传入。**
- `HitBoxConfig`（SO）只有手感参数：持续时长/冲量/伤害类型/冲击类别/抖镜三参/顿帧时长（HitBoxConfig.cs:11-33）；**几何（尺寸/偏移）不在 Config**——由 prefab 上的子 Collider2D 组合定义（HitboxMelee.cs:26-27），复杂形状靠摆碰撞体；
- **damage 不进 Config**：每次 `GenerateHitbox` 按发射者当前 AttackPower 传入（Hitbox.cs:191）——同一判定框随角色攻击力成长；
- Config 在 Init 时拷入 Hitbox 私有字段（:65-78）——换手感换 SO，不改代码。

**3. 静态工厂 `GenerateHitbox` 统一出生流程**（:175-199）。
Instantiate → 设 origin（伤害来源）→ 按 hasFriendlyDamage 决定 targetFaction（阵营语义：player/ally→enemy，enemy→friendly，其余→all）→ destroyTimer → 挂 parent（玩家攻击挂攻击挂点随人移动，敌人传 null）→ Init。玩家与敌人共用这一个入口。

**4. 双重去重 = "多段判定"与"穿透"的实现基座。**
`touchedColliders`（Collider 级，防同一碰撞体反复触发，:55）+ `alreadyHitItems`（iDamagable 级，防一个角色多碰撞体被多次结算，:111-119）。三种形态在这对基础上有不同策略（见下方差异表）。

**5. 近战的时序窗口。**
damagePoint（前摇）+ effectTime（生效窗）构成判定窗口（HitboxMelee.cs:17-19），effectTimer 用 **origin.FixedFrameInterval** 累计——判定节奏跟随攻击者的时间缩放（子弹时间里他的攻击判定也慢）。窗口外盒子重叠也不结算。检测是主动 `OverlapCollider` 轮询而非物理回调（collider.enabled 开关"无实际作用，仅方便查看"，:48）。

**6. 弹丸防隧穿。**
`RaycastAll(position, velocity, velocity.magnitude × fixedDeltaTime)` 覆盖上一物理帧位移（HitboxBullet.cs:83-84），按命中距离排序逐个结算——高速子弹不会穿墙。

**7. LOS 校验统一走一个扩展方法。**
`HasNoDamageObstacle`（MathTools.cs:123-132，射线打 Ground|Wall 层）：近战结算前逐目标校验（中间有墙不算命中）、爆炸在 CollideCheck 过滤、子弹检测时过滤——三种形态一套视线规则。

**8. 打击反馈与伤害解耦。**
`PlayHitEffect` = `TimeManager.FreezeTimeFor(顿帧)` + `CameraShaker.Shake`（Hitbox.cs:144-150），与伤害数值互不关心。触发策略按形态：近战首次命中才播、子弹命中且非格挡才播、**爆炸无论命中与否播且只播一次**（HitboxExplosion.cs:36-40）。

**9. Damage 是纯数据 DTO，iDamagable 是受击方最小契约**（Damagable.cs:9-15：`Hit(Damage)` + `Faction` + `HitboxCenter`）。
判定系统对"受击者是谁"零依赖——Entity、DamagableBox（可破坏物）都能挨打。

**10. 弹反（Counter）是一等结果。**
HitResultType 枚举含 Miss/Hit/Stucked/Blocked/Counter（Hitbox.cs:217）。子弹被弹反时**原地改写自身参数反咬**：速度反向、伤害改写、penetration=1、targetFaction 翻转、清去重表（HitboxBullet.cs:232-255）。

**11. ActionIgnoreMask：位掩码统一"锁"与"CD"两种需求。**
tag 位枚举 Move(0)/Action(1)/Dash(2)/Jump(3)/Interact(4)/All（ActionIgnoreMask.cs:4）。ActionIgnoreComponent 用链表存 {mask, timer}：**同 mask 合并取更长时间**不重复建条目（ActionIgnoreComponent.cs:41-50），倒计时用 FixedFrameInterval。被复用为四种语义：受击硬直=All、攻击锁移动=All、收招硬直=BusyFor(attackRecovery)、**突刺冷却=Dash 位**（PlayerThrust.cs:22-23）——一套机制，冷却就是"给自己上锁"。

**12. Displacement：曲线位移数据化。**
maxSpeed/length/speedCurve 三件套 SO（Displacement.cs:9-29）。LocomotionComponent.ForceMove 记方向并**取消面向耦合**（击退方向与面朝解耦，LocomationComponent.cs:74-80），RefreshFixedUpdate 按归一化 t 采样曲线覆写 rb.velocity.x，到时交还控制权。同一结构服务：受击击退 / 攻击前冲 / 突刺——打击感的"位移端"全数据化，调手感=调 SO。

## 二、工作逻辑（怎么运转）

### 完整命中链（玩家近战，从鼠标到掉血到反馈）

```
[输入]   PlayerInputController.OnUpdate → AttackCommand.CanExecute
         （动作机==None ∧ 落地 ∧ !IsIgnore(Action)）→ ChangeState(Attack)
[起手]   PlayerAttackState.Enter：ZeroVelocity + AddIgnore(All 动作锁)
         + Combat.BeginAttack() → ForceMove(attackForce) 攻击前冲
[判定生成] 动画事件 "AttackTrigger" → PlayerCombat.HitDetect
         → Hitbox.GenerateHitbox(prefab, origin, 攻击挂点, AttackPower)
[每物理帧] HitboxMelee.FixedUpdate：
           自毁计时 → CollideCheck（生效窗内 OverlapCollider → 阵营过滤 → 去重入列表）
           → HitResultCheck：LOS 校验 → Hit(target, damage)
[受击侧] Entity.Hit：格挡？→Blocked 短路；无敌？→Miss
         → DamageComponent.Hit：Owner.Interrupt（全体打断）+ Hit 动画
           + 击退方向计算（离心型=Chest−爆心）+ 面向攻击方 + ForceMove(hitRepel)
           + AddIgnore(硬直=All) + 血液粒子
         → 减伤 actual = damage × 100/(100+Defense)
         → healthManageComponent.ApplyDamage → AttributeSet.Modify
           → clamp→判变→Changed/AnyChanged 事件（飘字/血条订阅）
           → Health ≤ 0 ⇒ OnDied
[反馈]   首次命中：FreezeTimeFor(顿帧) + CameraShaker.Shake；格挡：截停本次攻击
[收招]   动画事件 "AnimEnd" → 回 None 状态 → Exit：BusyFor(收招硬直) + locomotion.Interrupt()
         （掐掉比动画长的前冲残速——否则"跑步动画但不位移"）
```

敌人侧对称：MeleeAttackState.Swing / RangedAttackState.Shoot 走同一个 GenerateHitbox
（timer 分段驱动，不依赖动画事件——敌人动画事件不可靠的设计取舍）。

### 三种 Hitbox 差异速查

| | 检测方式 | 命中上限 | Blocked 行为 | 销毁 |
|---|---|---|---|---|
| HitboxMelee | 子 Collider 重叠轮询 | 每角色 1 次 | **截停整次攻击**+播 Block | maxExistTime 到 → Destroy(GO) |
| HitboxExplosion | 重叠 + 爆心 LOS 过滤 | 无上限 | 仅该目标抵消，继续 | ⚠ Destroy(this) 仅删组件，GO 残留 |
| HitboxBullet | RaycastAll 防隧穿 | penetration 递减 | 立即 Stucked（碎片） | Stucked → 转 Debris 层 |

## 四、坑与约定

1. **已知瑕疵**：GenerateHitbox 里 hasFriendlyDamage 在 Init()（Config 拷入）**之前**读取
   （Hitbox.cs:184 vs :197）——Config 驱动的友伤开关不生效，只有 prefab 序列化值参与阵营判定。改这里时先修顺序。
2. 爆炸盒销毁是 `Destroy(this)`（组件级），GameObject 残留——排查场景里"看不见的空对象"先想到它。
3. 新攻击形态：继承 Hitbox 覆写 CollideCheck/HitResultCheck，别在基类加 if(形态)。
4. 行为锁的语义选择：锁动作用 All，冷却类用具体位（Dash）——All 会连 AI 硬直判定一起影响。
5. 判定窗口的计时源是 **origin 的** FixedFrameInterval（攻击者时间缩放），不是 Hitbox 自己的。

## 五、与相邻模块的边界

- 上游《玩家系统》：状态机与动画事件决定**何时**生成判定盒；模块（Combat/Thrust）编排前冲。
- 下游《GAS属性系统》：伤害数值落地唯一入口是 `ApplyDamage → AttributeSet.Modify`——打击盒永不直接改血。
- 下游《支撑服务·时间》：FreezeTimeFor 的顿帧按**真实时间**恢复（暂停/慢动作不影响恢复计时）。
