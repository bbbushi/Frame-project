# 游戏流程系统 — 设计与工作逻辑

> 代码：`Assets/GameFlowSystem/`（GameFlowManager、SceneRegistry、FlowSpawn、SpawnPoint、MainMenu）+ `Editor/FlowSmokeTest.cs`·`FlowValidation.cs`
> 定位：五期成果 + 六期方案对象——状态机 + 注册表驱动的转场管线，全项目切场景唯一合法入口。
> 前置阅读：《MOMS管理器框架》（命名空间白名单——本系统曾整体失联的根因）、《UI框架》（派生闸门）

---

## 一、设计思路（为什么这么设计）

**1. 状态 + 注册表驱动转场。**
`FlowState{MainMenu, Loading, Playing, GameOver}`（Victory 为六期方案预留值）；场景名不硬编码，全部走 `SceneRegistry` SO（sceneId/displayName/isMainMenu）——入口即校验拼写，不等 LoadSceneAsync 返 null 才发现。注册表与 Build Settings 的对齐靠编辑器菜单 `Flow/校验场景注册表` 兜底（"登记和 Build 是两处手工维护，靠人脑对齐必漏"）。

**2. 转场编排借用 UI 派生闸门（零自己的闸门代码）。**
LoadingPanel 配成 Exclusive+World → Show 的瞬间四期派生自动锁输入/停世界。流程系统与 UI 系统的接缝只有两处：Show/Hide LoadingPanel + Esc 护栏读 `Current`。

**3. 静态门面 = 全项目唯一合法入口，内部各自校验状态合法性。**
禁止裸 `SceneManager.LoadScene`（约定速查第 4 条）。并发护栏：Loading 中拒绝并发转场（两条 Routine 同时 LoadSceneAsync = 乱套）。

**4. GameOver 是纯状态位非场景（有教训的决策）。**
原实现 TransitionTo("GameOver")：场景不存在，且转场后 State 落回 Playing——"GameOver 活不过一次转场"（GameFlowManager.cs:76-78 注释）。结算语义 = 状态位 + 面板，不落场景。

**5. namespace 必须在 MOMS 白名单内（P0 教训，2025-10 已修）。**
五期方案曾写成 `namespace GameFlowSystem` → 反射扫描不认 → **从未注册**，StartLevel/ReloadCurrent 全部静默无效；流程冒烟因反射注入迷你 MOMS 绕过扫描而全绿（假阴性）。现固定为 `Managers.GameFlow`——新流程类一律进这个命名空间。

## 二、工作逻辑（怎么运转）

### 门面行为表

| 门面 | 前置校验 | 行为 |
|---|---|---|
| `StartLevel(sceneId)` | Resolve 判空静默；注册表查不到拒绝；**同场景拒绝**（重开语义归 ReloadCurrent） | TransitionTo |
| `ToMainMenu()` | 按 isMainMenu 标记找，不硬编码场景名 | TransitionTo |
| `ReloadCurrent()` | 仅 Playing/GameOver 态（主菜单无"重开"） | TransitionTo(当前场景) |
| `GameOver()` | 仅 Playing → 置 GameOver | 纯状态位，无加载 |
| `Current` | 静态只读 | UI Esc 护栏读这个 |

### 转场 Routine 逐步（:105-127）——本项目最重要的时序表之二

```
1. prevState = State; State = Loading                    [先落 Loading = 并发护栏生效]
2. UIManager.Show("LoadingPanel")
   [历史坑：曾 Show("Loading")/Hide("LoadingPanel") 键名不一致——Hide 永远找不到，
    黑幕关不掉 = 输入锁死]
3. op = SceneManager.LoadSceneAsync(sceneId)
   null 分支（"注册表有但 Build 没有"的典型形态）：
   LogError + Hide LoadingPanel + State = prevState 退出
   [不留 Loading 僵尸态——否则卡死所有后续转场]
4. while(!op.isDone) → LoadingPanel.ReportProgress(op.progress) → yield return null
   [allowSceneActivation=true 时 isDone 才是真完成，progress 停在 0.9]
5. 此刻 sceneLoaded 已触发 = 落点校准完成、新场景 Awake 全跑完
6. UIManager.Hide("LoadingPanel")
7. State = IsMainMenu(_currentScene) ? MainMenu : Playing  [Hide 之后落定——Esc 护栏靠 Loading 期成立]
```

### 落点校准

```
SceneManager.sceneLoaded → OnSceneLoaded (:132-136)
  → _currentScene = scene.name; FlowSpawn.Calibrate()
FlowSpawn.Calibrate：FindFirstObjectByType<SpawnPoint>() + <Player>()
  两者都在才 SetPositionAndRotation(sp.position, sp.rotation)
  ["玩家 prefab 化前的兼容落法：场景继续摆玩家，SpawnPoint 保证摆哪都会被校正"]
SpawnPoint：零逻辑标记组件（将来检查点 = 同组件加 id 扩展）
```

### 主菜单与按钮转发

```
MainMenu（MainMenu.cs:11）：UGUI OnClick 只能绑实例方法，静态门面须借它中转
  StartGame() => GameFlowManager.StartLevel(startSceneId)   [Inspector 填，默认 BABEL1]
  QuitGame()  => Application.Quit()
主菜单是场景本体 UI 而非面板（寿命=场景寿命；做成面板会有 DDOL 残留/autoShow 无场景概念/
Esc 栈污染三成本——决策记录见《游戏流程闭环设计方案.md》）
```

### 验证工具（Editor/）

- **FlowSmokeTest（纯逻辑，非 Play 可跑）**：只测拒绝路径 + 状态位。红线：**允许路径会真 LoadSceneAsync**——编辑器非 Play 调它真的会换场景，所以冒烟的反射注入迷你 MOMS 只喂拒绝分支。
- **FlowValidation**：`Validate`（注册表自检：空条目/空 id/重复 id，纯函数）+ `ValidateBuildList`（每条注册必须在 Build Settings 找到且 enabled——缺了正是 LoadSceneAsync 返 null 的直接原因）+ 反向信息（Build 有但未登记）。

## 四、坑与约定

1. **切场景只走门面**，禁止裸 LoadScene——落点校准/Loading 闸门/状态落定全在管线里。
2. 新场景接入三件事：场景文件 + 注册表加条目 + Build Settings 勾选——做完跑 `Flow/校验场景注册表`。
3. LoadSceneAsync 返 null 的两大原因：不在 Build 列表 / 未勾 enabled——Routine 的 null 分支会兜住并回 prevState，看到"转场失败"先跑校验菜单。
4. 门面键名一致性：Show/Hide 的 panelId 必须逐字相同（"Loading"案）。
5. 状态落定在 Hide 之后——依赖"Loading 期"做护栏的逻辑（如 Esc）别在读到 Playing 前动作。
6. 冒烟测试红线：允许路径（会真加载场景的分支）永远不进非 Play 冒烟。

## 五、与相邻模块的边界

- 上游《UI框架》：Show/Hide LoadingPanel 借派生闸门；Esc 护栏读 Current；VictoryPanel/DeathPanel 走面板栈。
- 上游《实体与组件模型》：死亡链终点（Player DeathState → ReloadCurrent；六期方案 3.6 改 GameOver()+DeathPanel）。
- 下游《支撑服务·时间》：LoadingPanel 的 World 暂停经 TimeManager.PauseScale 生效。
- 六期挂账（方案见《游戏流程闭环设计方案.md》）：LevelComplete 门面+Victory 枚举、ExitPortal 出口触发器、FlowActions 面板转发器、面板三件套（VictoryPanel/DeathPanel/PausePanel 补按钮）、死亡接线改造、HUD 归属 Flow。
