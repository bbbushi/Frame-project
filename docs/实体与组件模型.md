# 实体与组件模型 — 设计与工作逻辑

> 代码：`Assets/Script/Entity.cs`、`Assets/Component/EntityComponent.cs` 及各组件、`Assets/Script/Player/Player.cs`、`Assets/Script/Enemy/Enemy.cs`
> 定位：Player/Enemy 共同的骨架——Entity 做编排者，组件做器官，手动刷新链是全项目第二套"自己管时序"的机制。
> 前置阅读：《MOMS管理器框架》（时间缩放体系在其中）

---

## 一、设计思路（为什么这么设计）

**1. Entity = 组件编排者（Orchestrator），不是逻辑容器。**
Entity 自己几乎不含战斗逻辑，只做三件事：缓存子组件引用（Entity.cs:15-22，全部 `[HideInInspector] public`，给模块和状态直接访问）、按固定顺序手动驱动组件刷新、实现 `iDamagable` 门面（Hit 先判格挡/无敌再转发，:188-196）。逻辑都在组件和模块里，Entity 只管"谁、什么时候"。

**2. 组件获取用 `GetComponentInChildren` 而非 `GetComponent`**（:91-98）。
允许组件挂在子节点（视觉模型/碰撞体分层摆放）。代价：组件 Init 不能依赖 Unity 的 Awake 随机序，必须在 Entity.Start 里显式统一调用（:102-109）。

**3. 手写刷新链而非 Unity 消息。**
`EntityComponent` 基类定义四个虚方法（EntityComponent.cs:37-40）：`Init / RefreshUpdate / RefreshFixedUpdate / Interrupt`，**全部无参数**——时间增量通过属性 `FixedFrameInterval => Time.fixedDeltaTime × LocalTimeScale`（:33）自取。理由：绕开 Unity 魔法消息的开销与顺序不可控，每个实体的刷新时序完全可读、可排、可打断（Interrupt）。

**4. 每实体时间缩放体系（全项目的时钟总约定）。**
```
LocalTimeScale   = 实体自己的缩放（动画驱动等）
TimeScale        = LocalTimeScale × TimeManager.GlobalTimeScale   (Entity.cs:50)
FixedFrameInterval = Time.fixedDeltaTime × TimeScale              (Entity.cs:64)
```
所有计时——组件冷却、Hitbox 生存期（Hitbox.cs:84）、效果 Tick（HealthManageComponent.cs:59）——统一用 FixedFrameInterval。于是全局顿帧/子弹时间**自动传导**到每个实体的每个时钟，无需各处适配。HealthManageComponent.cs:57-58 留有血泪注释：曾误传 TimeScale（倍率恒 1）导致毒时钟快 50 倍——这条约定是踩坑后的统一。

**5. Owner 懒查找 + 优雅降级。**
EntityComponent 用 `GetComponentInParent<Entity>()` 懒查 Owner 并缓存；找不到只警告一次，时间属性退化为全局时间而非 NRE（EntityComponent.cs:12-35）。

**6. 两套"组件"并存、职责分明。**
- `EntityComponent`（MonoBehaviour，"身体器官"）：横切能力（检测/移动/受击/血量/行为锁），有刷新协议，被 Entity 主动 tick；
- `EntityModule`（纯 C# 类，"技能包"，详见《玩家系统》）：领域玩法逻辑，无刷新协议，被命令/状态机主动调用。
分界一句话：**器官被动被泵，技能主动被调**。

**7. 池化状态重置集中化。**
`ClearBattleTimers()`（Entity.cs:40-44）统一清无敌/格挡计时；Enemy 的 OnSpawnFromPool/OnReturnToPool 都调它。**Entity 本身不实现 IPoolable**——池化是子类（Enemy）按需实现的可选能力，Player 不池化。

**8. Player.Awake 的防御性设计**（Player.cs:51-59）。
关键组件缺失时 `SetActive(false)` 而非仅 `enabled=false`——因为 `Player.Instance` 用 FindObjectOfType，能找到"组件禁用但 GO 激活"的实例，会让 PlayerInputController 每帧 NRE。

**9. 事件订阅位置与池化的关系**（Enemy.cs:78-95 注释）。
OnDied 的订阅/退订放在 **OnEnable/OnDisable**，不放 Start/Awake——池化复用第二只起就收不到事件了。死亡链顺序有意安排：先 `aiComponent.OnOwnerDied`（先进死亡态）再 `Die`（再回收进池）。

## 二、工作逻辑（怎么运转）

### 生命周期

```
Awake (:89)    缓存 rb/anim/spriteRenderer + 五大组件引用（GetComponentInChildren）
Start (:102)   显式 Init，顺序：detection → damage → locomotion → healthManage → actionIgnore
```

### FixedUpdate 刷新链（Entity.cs:120-140）——本项目最重要的时序表

```
Entity.FixedUpdate
 1. invincibleTimer / blockTimer 自减                          (:123-124)
 2. detection.RefreshFixedUpdate()      地面/墙/平台传感器 → 平台穿透层切换 (:126)
 3. locomotionComponent.RefreshFixedUpdate()   强制位移积分（击退/前冲曲线驱动 rb.velocity）(:129)
 4. damageComponent.RefreshFixedUpdate()       受击持续表现（血液粒子）(:132)
 5. healthManageComponent.RefreshFixedUpdate() → AttributeSet.TickEffects
                                        （Duration 到期回退 / Period 周期跳——毒/铁壁的时钟全在这）(:135)
 6. actionIgnoreComponent.RefreshActionIgnore()  行为锁倒计时移除 (:138)
```

**子类追加规则：追加在链尾。**
`Enemy.FixedUpdate = base.FixedUpdate() + aiComponent.RefreshFixedUpdate()`（Enemy.cs:29-33，注释明言"AI 决策在组件刷新之后"——AI 读到的是本帧最新的物理事实）。Player 不重写 FixedUpdate，只在 Update 层追加三个表现组件的 RefreshUpdate（Player.cs:76-83）。

### Interrupt 广播（Entity.cs:146-153）

`GetComponentsInChildren<EntityComponent>()` 逐个 `Interrupt()`。典型用途：受击时全体组件打断（清位移队列）→ DamageComponent 再施加新击退，顺序不冲突。

### 池化流（与 ObjectPoolManager 的接口）

```
取：ObjectPoolManager.GetEnemy → pool.Get() → OnSpawnFromPool()
    （Revive 回满血 + ResetAI + ClearBattleTimers，ObjectPoolManager.cs:127-139）
还：OnDied → Die → Release → OnReturnToPool()
    （StopAllCoroutines/清速度/清计时器 → 重置 Transform → SetActive(false)，:99-116）
```
Release 找不到映射时回退 Destroy（:172）——池外对象也能安全走这条链。

## 四、坑与约定

1. **第二大坑**：给组件加新 Refresh 逻辑，必须同时在 Entity（或 Player）的 FixedUpdate 里接线——
   漏了就是静默不运行（飘字/毒钟两案皆此）。加完在 FixedUpdate 链上肉眼确认一遍。
2. **一切实体侧计时用 `FixedFrameInterval`**，绝不传 `Time.timeScale` 或裸 `Time.deltaTime`
   （FixedUpdate 里 deltaTime == fixedDeltaTime，但乘缩放才是对的）。
3. 池化对象的事件订阅放 **OnEnable/OnDisable**，不放 Start/Awake。
4. 组件引用是 `GetComponentInChildren`——组件挪到子节点没事，挪出实体层级就断。
5. 新组件的 Init 顺序在 Entity.Start 里手排——加组件要记得插进这个顺序。

## 五、与相邻模块的边界

- 上游《MOMS管理器框架》：GlobalTimeScale 从 TimeManager 流入实体时钟体系。
- 下游《打击盒与动作系统》：Hitbox 计时同样吃 FixedFrameInterval；DamageComponent 是打击链的受击端点。
- 下游《GAS属性系统》：HealthManageComponent.RefreshFixedUpdate 是效果时钟的唯一驱动位。
