# 支撑服务 — 设计与工作逻辑（输入/时间/音频/池/相机/存档/对话）

> 代码：`Assets/Component/InputComponent/`、`Assets/Time System/`、`Assets/SFX&Music System/`、`Assets/Pool System/`、`Assets/Component/Camera Component/`、`Assets/SavingSystem/`、外部包 `com.otus.dialogue`
> 定位：七个横切服务，各自短小独立；共同的口味是"真实时间计时 + 静态门面 + 配置 SO"。

---

## 一、输入 InputComponent

**设计思路：三段命令模式。** InputManager（硬件读取层，每帧缓存三态字典）→ PlayerInputController（Invoker，动作→命令映射）→ IPlayerCommand（领域命令，直接访问 Player 模块）。键位用 `PlayerInputData` SO 可重绑（运行时 `SetInputData` 整表替换），SO 缺失回退硬编码默认键位。用旧 Input Manager（KeyCode 轮询），非新 Input System。

**关键设计点：**
- `IsUICancelPressed`（Esc）是**独立导航通道**：独立字段不进 PlayerAction（那是战斗动作语义域），且**故意不走 IsInputEnabled**——"Exclusive 面板开着时恰恰只有 Esc 能用"；
- **对话屏蔽**在 RefreshFrameState 开头：`IsAnyPlaying → 只更新移动输入 + uiCancelPressed=false + return`——"不清的话进对话那帧恰好按过 Esc，true 卡整个对话期，UIManager 每帧退栈退光"；
- `ReadKey` 按绑定**单一触发相位**写对应字典（Down/Hold/Up 三态不同时写）；
- 查询层全部带全局开关短路：`IsPressed => IsInputEnabled && GetValue(...)`。

**ActionIgnore 的类型位置**：运行时容器 `ActionIgnoreComponent` 在 `Assets/Component/`（LinkedList{mask,timer}，FixedFrameInterval 倒计时，同 mask 取更长）；位掩码类型 `ActionIgnoreTag/Mask` 定义在 `Assets/ActionSystem/ActionIgnoreMask.cs`（namespace ActComponents）。消费方：AttackCommand(Action)、MotionStates(Move)、PlayerLocomotion(Jump)、PlayerThrust(Dash)、EnemyAIComponent(All)。

## 二、时间 TimeManager

**设计思路：四因子缩放。** `scale = slowScale(子弹时间) × pauseScale(UI 暂停) × frameFreezeScale(hitstop) × debugScale`，任一变更即重乘写入 `Time.timeScale`（ResetGlobalScale:211-220）。**冻结/慢动过渡一律用真实时间计时**（realtimeSinceStartup/unscaledDeltaTime）——冻结期间 Time.deltaTime 本身 = 0，用游戏时间计时会永久卡死。

**关键机制：**
- `FreezeTimeFor(duration, interrupt=true)`：仅非冻结态记录恢复目标（避免把 0 记进去）；已冻结只更新终点；interrupt=重计时，false=延长取最远。调用方：Hitbox 命中帧（顿帧+屏震）。
- `SetSlowScaleSmooth(target, duration)`：MoveTowards 平滑过渡（unscaled 驱动，暂停中过渡继续）。当前 SlowScale 闲置（API 就绪）。
- `LocalTimeScale`：独立于四因子的实体级缩放；set 时算 ratio 广播 `OnLocalTimeScaleChanged(newScale, ratio)`——Player 订阅做 `anim.speed=新倍率; Velocity×ratio`。
- `DriveTimers`：静态 Timers 列表**倒序遍历**（Tick 回调里 new Timer 会 Add 到尾部，倒序防本帧误 Tick）；按 TimerType 分发增量；Tick 回调 try/catch（单个异常不打断其余 Manager）；Destroy 只置标志、末尾统一 RemoveAll。
- `Timer` 类（名为泛型实为事件回调型）：构造即注册进静态列表；Set/Cancel/Destroy + implicit float。

## 三、音频 SFXManager / MusicManager

**SFXManager（MOMS 范本管理器）：**
- AudioSource 池（initialPoolSize 8 → maxPoolSize 24），池满丢弃本次不阻塞；
- 回收由 OnUpdate 轮询**预计回收时刻**驱动：`returnTime = unscaledTime + clip.length / |pitch|`（pitch 越高回收越早；负 pitch 取绝对值保时长）——不监听 isPlaying；
- 随机 clip/volume/pitch 三随机防重复感；`PlayFootstep` 向下 Raycast 按地面材质选音效，miss 走默认。

**MusicManager：**
- 固定**双 AudioSource 交叉淡入淡出**，渐变由 OnUpdate 状态机驱动（无协程分配）：new 源 Lerp(0,1)、old 源 Lerp(1,0)，到点交换引用；
- `PlayMusic(type)`：同曲目且无渐变进行中→直接 return（防重复）；渐变进行中→强停旧渐变的 old 源再起新渐变（打断语义）；首次播放无 old 源=纯淡入；
- 三曲目 `MusicType{Normal, Start, fight}`；无条件 DDOL；首帧延迟启动（"避免 Initialize 还未完全结束就播放"）。
- **现状：框架完整，音频资产为零**（配置 clip 全空）——七期内容。

## 四、对象池 ObjectPoolManager

**设计思路：唯一刻意不走 MOMS 的管理器**（MonoBehaviour Singleton）——"池是场景物体生命周期而非纯逻辑服务"。用 Unity 官方 `UnityEngine.Pool.ObjectPool<GameObject>` 按 enemyType 建池。

**双向字典**：正向 `_objectPools[type]→pool`（取时查），反向 `_spawnedToType[instance]→type`（回收时调用方免传类型名）。

**链路要点：**
- `GetEnemy`：池 miss LogError 返 null → pool.Get() → 记反向映射 → **重置 Transform**（注释"重要！"）→ SetActive(true) → `IPoolable.OnSpawnFromPool()`；
- `Release`（统一回收口）：反向查类型→池 Release；查不到（非池对象）**回退 Destroy**——敌人代码可以无脑 Release；
- `ReturnToPoolInternal`：**先调 OnReturnToPool 回调** → 复位 Transform → 挂回 root → SetActive(false) → 清反向映射；
- actionOnDestroy 里清反向映射（池满丢弃/Dispose 时防残留）。
- **现状：无代码调用 GetEnemy**（敌人手工摆放）——接入生成器是挂账项。

**敌人侧配套（Enemy: IPoolable）**：OnSpawnFromPool = Revive（内含 ClearEffects）→ ResetAI → ClearBattleTimers → 变白；OnReturnToPool = StopAllCoroutines + 清 Timer + 速度清零 + 变白。事件订阅标准位 = OnEnable/OnDisable。

## 五、相机 CameraShaker

**设计思路：偏移计算与相机应用分离。** CameraShaker 是 Singleton 只算 `shakeOffset`（Vector2），**不碰任何相机**；所有虚拟相机统一从静态 `ShakeOffset` 取值自己应用（PlayerCameraComponent.cs:77，多虚拟相机共享此源）。

**实现细节：**
- 抖动是**解析式正弦半波包络**非 Perlin：`y = |sin(π·repeat·progress)|^0.5 × (1-progress)`——整流^0.5 提峰值包络 × 线性衰减，repeat=半波个数（多次脉冲渐弱）；多条抖动叠加；
- LateUpdate 用 `Time.unscaledDeltaTime`——hit-stop 冻结期间抖动仍要播完（与 FreezeTimeFor 同帧触发配套）；
- `CameraLock(f)`：Timer 懒创建 `new Timer(0, TimerType.normal)`——锁定期内 Shake 拒绝（防 UI 转场抖动抢镜）；
- **坑位注释**：不在 Awake 里 new Timer——重复实例 Destroy 延迟到帧末，其余 Awake 代码仍执行，会向静态 Timers 注入永不清理的计时器。

## 六、存档 SavingSystem

静态工具类（namespace `SavingSystemTutorial`），**JSON 文件与 PlayerPrefs 两套平行 API**（载体不同、签名对称，均 JsonUtility、全 try/catch 不抛）：
- JSON：persistentDataPath/名.json——`SavingByJson / LoadFromJson<T> / DeleteSaveFile`；
- PlayerPrefs：key=文件名存 JSON 字符串——对称三件。
- **坑**：LoadFromJson 缺文件走 catch 打**红色 LogError**——所以 JsonProgressStore.Load 先 File.Exists 预检（首运行防误报）。
- 当前唯一业务消费者 = 引导进度；游戏存档（关卡进度/检查点/继续游戏）八期规划。

## 七、对话 com.otus.dialogue（外部包，本地路径引用）

**DialogueManager**：MonoBehaviour **懒创建自举单例**（场景零摆放；EnsureInstance 触发 Awake 里的 UI 构建；DDOL）。状态机 `{Idle, Typing, WaitingAdvance, Choosing}`；打字机用 TMP `maxVisibleCharacters` 递增（全文只设一次、布局只算一次）。
**项目侧最依赖的公开面**：
- `static bool IsAnyPlaying`——InputManager 对话屏蔽与 GuideManager 对话暂停都读它；
- 事件：DialogueStarted / NodeBegan / CommandReceived（core 只派发不解释，扩展包订阅解释 bgm=/sfx= 之类）/ DialogueEnded；
- `StartDialogue` 幂等（播放中忽略新对话）；`ResetSession`（清变量/backlog/已读，不动在播状态机）；`CaptureSnapshot/RestoreSnapshot`（供存档）。

**DialogueTrigger**（interaction 包）：两模式 `InteractKey（靠近+按键，默认 E）/ AutoStart（延迟自动）`。玩家识别认**碰撞体自身或 attachedRigidbody 根的 Tag**（玩家碰撞体常挂子物体、Tag 设根上）。once=运行期单次标记（不入存档）。OnDisable 收尾防提示残留；Reset 编辑器首挂自动补 BoxCollider(isTrigger)。

## 坑与约定（跨服务汇总）

1. **凡"冻结/暂停期间还要走"的计时，一律 unscaled/realtime**：UIFade、DamageNumber、CameraShaker、TimeManager 冻结恢复、引导 Tick——新写计时先问"暂停时它该不该走"。
2. Timer 构造即注册静态列表：状态/积木里用**纯 float 计时**，Timer 留给跨帧回调语义；重复单例的 Awake 里别 new Timer。
3. 音频/池的"满"策略都是丢弃+警告不阻塞——听不到音效/生成失败先查池与配置资产。
4. 对话屏蔽的两端都在别处读 `IsAnyPlaying`（输入/引导）——对话包升级时这是兼容契约。
5. ObjectPoolManager 的 Release 对非池对象回退 Destroy——调用侧无需判断"它在不在池里"。

## 与相邻模块的边界

- 输入 ←《玩家系统》命令模式 / 《UI框架》闸门写入 IsInputEnabled / 《引导系统》步骤接管。
- 时间 ←《打击盒》FreezeTimeFor、《UI框架》PauseScale、《实体》GlobalTimeScale 汇入 FixedFrameInterval。
- 池 ←《敌人AI》OnSpawn/ResetAI 生命周期契约。
- 存档 ←《引导系统》JsonProgressStore（唯一消费者）。
- 对话 ← 输入屏蔽 + 引导暂停两处桥接；（待接）节点命令解释器与结束事件。
