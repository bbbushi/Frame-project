# 引导系统 — 设计与工作逻辑

> 代码：`Assets/GuideSystem/`（Core/ 纯逻辑 + Integration/ 项目适配）、表现层 `Assets/UISystem/Integration/GuideViewUGUI.cs`
> 定位：数据驱动步骤机——条件/命令多态序列化，核心层零项目依赖可整体移植。
> 前置阅读：《UI框架》（Guide 层、表现层降级）

---

## 一、设计思路（为什么这么设计）

**1. 核心层/适配层物理分离（本系统最独特的决策）。**
`Core/`（GuideData/GuideStep/GuideEngine/条件/命令/视图接口/进度接口）是纯 C# + SO，**不引用任何项目服务**——移植其他项目时核心层原样拷贝、只重写 GuideManager。`Integration/` 才碰 GameManager/InputManager/SavingSystem。条件体系的分工就是这条线的体现：AutoComplete/Composite 在 Core（只依赖 context），PlayerAction/Predicate 在 Integration（可调 GameManager）。

**2. 数据驱动步骤机。**
GuideData(SO) → List<GuideStep>；每步 = 文案 + 高亮键 + 完成条件 + 超时 + 去向 + 进入命令。条件/命令用 `[SerializeReference, SubclassSelector]` 多态序列化（Unity 2022.3 没有类型下拉，自定义 drawer 补齐，Core/SubclassSelectorAttribute.cs:10）。

**3. 事件解耦。**
引擎只广播 6 个事件（Guide/Step Started/Completed + Finished/Aborted），存档、表现层、断点续传全挂事件上，引擎不知道它们存在。

**4. 命令 = 可逆副作用（LIFO 回滚）。**
进入顺序 Execute、任何原因离开逆序 Revert。⚠ 运行时状态严禁写命令自身字段——命令实例属于 SO 资产，Editor 下会持久污染；一律放 `Scratch` 字典。

**5. 引擎进度落盘到"每步"。**
"开跑即记录，崩溃也能断点续传"；每步完成记 `runningStepIndex = 当前+1`（记"下一步"，已完成步不重播）——"文件极小，崩溃后断点天然准确"。

## 二、工作逻辑（怎么运转）

### 数据结构

`GuideStep`（Core/GuideStep.cs:25）核心字段：
- `nextStepId` 三态：**留空 = 顺序 index+1；填 stepId = 显式跳转（分支/跳步/回环）；填哨兵 `"__end__"` = 提前结束**（EndStepId 常量，:28）；
- `timeoutSeconds + timeoutAction{None, CompleteStep, AbortGuide}`；
- `onEnterCommands`（List<IGuideStepCommand>）；
- `GuideStepContext` = 步骤只读快照（供表现层）；运行时状态在 `GuideCommandContext.Scratch`。

### GuideEngine 推进（Core/GuideEngine.cs）

```
Start(guide, startIndex)：
  空/无步骤 → 不启动；已在跑 → 先 Stop(false)
  两遍校验：①建 stepId→index 索引（非空且唯一）②校验 nextStepId 可解析
  任一无效只 LogError 全局不启动（配置损坏不拖垮调用方）

EnterStep(index)：new Scratch → 记 index/elapsed → 顺序执行 onEnterCommands
  （SerializeReference 引用丢失会静默 null——逐个判空跳过并 LogError）
  → StepStarted 事件 → 缺条件 LogError（将空等到超时）

Tick(dt)：_elapsed += dt
  超时分支：timeout 到 → AbortGuide 则 Stop(false)，否则 CompleteCurrentStep
  条件分支：condition.IsSatisfied(ctx) → CompleteCurrentStep

CompleteCurrentStep：StepCompleted → ExitStep → 解析 nextStepId
  → 越界/-1 → GuideFinished；否则 EnterStep(next)

ExitStep：逆序执行 cmd.Revert(ctx)（i 从 Count-1 到 0）→ Scratch 置 null
Stop(markCompleted)：补发事件走同一 ExitStep；false = 发 GuideAborted
```

### 条件与命令清单

| 层 | 类型 | 语义 |
|---|---|---|
| Core | AutoCompleteCondition | ElapsedSeconds>=duration 纯时间自完成 |
| Core | CompositeCondition | Any/All 聚合子条件，可嵌套 |
| Integration | PlayerActionCondition | 判 InputManager 的 IsPressed/Held/Released × Down/Hold/Up |
| Integration | PredicateCondition | `predicateKey` 查静态注册表 `Registry<string, Func<ctx,bool>>`；未注册 key LogError+false 防死锁 |
| Integration | SetInputEnabledCommand | Execute 先把旧值存 `Scratch["prev"]` 再写 IsInputEnabled（演出步骤锁输入）；Revert 取回恢复 |
| Integration | PlaySoundCommand | PlaySFX；无需回滚，Revert 留空 |

### GuideManager 宿主（Integration/GuideManager.cs:22）

```
Initialize（同步段）：
  Load data/guide/GuideLibrary（null 仅警告、空库运行）
  → new JsonProgressStore + Load → _progress
  → new GuideEngine + 订阅 5 事件 → CreateUguiView
  → 扫描 autoStart && !IsGuideCompleted 逐个 StartGuideInstance(resumeIfIncomplete:true)

事件 → 存档链：
  GuideStarted   → runningGuideId + stepIndex=0 + Save（开跑即记录）
  StepCompleted  → runningStepIndex = ctx.StepIndex + 1 + Save（记"下一步"）
  GuideFinished  → completedGuideIds 去重追加（autoStart 不再触发）→ ClearRunning
  GuideAborted   → 仅 ClearRunning（中断 = 下次从头）

OnUpdate：DialogueManager.IsAnyPlaying → return（对话期暂停引导，防文案互顶/输入屏蔽空转）
  否则 engine.Tick(Time.unscaledDeltaTime)  [timeScale=0 时 Auto 步骤仍推进——引导面板常配 World 暂停]

断点续传（StartGuideInstance）：引擎在跑拒绝（单实例）；已完成拒绝；
  resumeIfIncomplete && runningGuideId==guideId && 0<index<Count → 从 runningStepIndex 起步

门面四件：IsGuideCompleted / StartGuide / StopGuide / ResetProgress
  （ResetProgress：先 Stop(false) 走 Aborted 清断点 → _store.Clear() 删文件 → 内存归零）
```

### 存档与表现层

- `JsonProgressStore` 包装 SavingSystem：Load 前**先 File.Exists 预检**（SavingSystem 缺文件打红色 LogError，首运行会误报）；Save=`SavingByJson("guide_progress")`；Clear=DeleteSaveFile。备选 `PlayerPrefsProgressStore`（key="Guide.Progress"）。
- `GuideProgressData` 刻意平坦（List<string>+string+int）——**JsonUtility 不支持 Dictionary 与多态，是扩展此结构的红线**。
- 表现层三级降级：Guide 层根拿不到 / GuidePanel prefab 缺失 / 根上无 IGuideView → 全部降 `NullGuideView`（残骸 Destroy 防空横幅永久挡 Guide 层）。`GuideViewUGUI`：ShowStep 填三段 TMP + SetActive(true)。

## 四、坑与约定

1. **已知偏差——`PredicateCondition.RegisterAll` 只存在于注释**（GuideManager.cs:19/194/217 提到，代码里无实现无调用）：目前游戏侧谓词零注册，配置了未注册 key 的 PredicateCondition 会每帧 LogError 且永不满足。要用谓词条件先补注册（或在 GuideManager.Initialize 里建 RegisterAll）。
2. 命令实例是 SO 资产的一部分——**运行时状态只能写 Scratch**，写命令字段会在 Editor 下持久污染资产。
3. 步骤的 nextStepId 写错不会启动时报——Start 只校验"可解析"，跳到错误但存在的 stepId 是合法的。
4. `GuideProgressData` 加字段只能加平坦类型（string/int/List<string>），JsonUtility 不认 Dictionary/多态。
5. 引导 Tick 用 unscaledDeltaTime——想"暂停世界时引导也停"的步骤，别用 AutoCompleteCondition 计时。
6. 对话期间引导自动暂停（OnUpdate 拦截），对话结束自动恢复——引导文案与对话互斥是有意设计。

## 五、与相邻模块的边界

- 上游《MOMS管理器框架》：依赖 InputManager（拓扑序保证同帧先刷输入后判条件——"删了会按键晚一帧"）+ UIManager。
- 上游《UI框架》：Guide 层挂 GuideViewUGUI；SetInputEnabledCommand 是输入闸门的第二写入者。
- 上游《支撑服务·对话》：IsAnyPlaying 是引导暂停开关。
- 下游《支撑服务·存档》：JsonProgressStore 是 SavingSystem 目前唯一业务消费者。
