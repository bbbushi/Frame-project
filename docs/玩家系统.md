# 玩家系统 — 设计与工作逻辑

> 代码：`Assets/Script/Player/`（PlayerStateMachine、PLAYERSTATE/）、`Assets/Modules/`、`Assets/Component/PlayerAnimatorComponent.cs`、`PlayerModuleControlComponent.cs`、`Assets/Component/InputComponent/Commands/`
> 定位：双层状态机 + 模块化宿主——移动层与动作层正交，功能拆成可配模块。
> 前置阅读：《实体与组件模型》（EntityModule 契约、ActionIgnore）

## 一、设计思路（为什么这么设计）

**1. 双层状态机 = 两台独立状态机实例（互斥单活），不是一台带优先级。**
`PlayerAnimatorComponent.Init` 装配两台泛型 `PlayerStateMachine<TId>`（PlayerAnimatorComponent.cs:40-41）：
- `MotionMachine`（None/Ground/Air）——"回答人在哪，由物理事实驱动，持续运行"；
- `ActionMachine`（None/Attack/Thrust/Death）——"回答人在干什么，持锁期间抑制移动层输入"。
互斥规则：任意时刻只有一台机有实际状态——动作层进 Attack/Thrust/Death 时移动层让位进 None；动作层回 None 时按物理事实恢复 Ground/Air（PlayerAnimatorComponent.cs:7-9）。

**2. 守卫三层 API（拒绝式：未声明拒绝的一律允许）**（PlayerStateMachine.cs:18-22）：
- `ForbidAllFrom(id)`——终态声明（Death 拒绝一切转出，后续新状态也自动被覆盖）；
- `ForbidAllBetween(...)`——互斥组（Attack/Thrust 组内互转全拒，进出均经 None）；
- `Forbid(from,to)`——单点例外。
结构规则优先于逐对规则（DenyReason 实现顺序，:143-153）。实际只装动作层禁令：`ForbidAllFrom(Death)` + `ForbidAllBetween(Attack, Thrust)`（PlayerAnimatorComponent.cs:56-60）——"任意状态→Death 默认允许，即死亡可打断一切"。

**3. 转换纪律。**
一切切换走 `ChangeState/Request`，不直接改 Current；`transitioning` 防重入——"Exit/Enter 内不允许再切状态"（:98-102）；`Transitioned` 事件在 transitioning 复位**之后**触发——"订阅者可安全发起后续转换（跨机联动用）"（:43-45）。自转换静默返回 true。

**4. 跨机联动集中在宿主，状态类不感知跨机事务**（PlayerAnimatorComponent.cs:112-128）：
```csharp
if (to == ActionStateId.None)   MotionMachine.ChangeState(grounded ? Ground : Air); // 动作结束交还姿态
if (from == ActionStateId.None) MotionMachine.ChangeState(None);                    // 进动作让位
```
推论：动作中死亡走"进动作"分支（motion 已是 None，自转换静默）；Death 是终态永不回 None，motion 永不恢复。

**5. 动画三分法**（PlayerState.cs:10-12）：
- **姿态**：状态 Enter 的 CrossFade 直控（animStateName=null 静默跳过，如 Death 暂缺剪辑）；
- **连续量**：Blend Tree（GroundMove=xvelocity / Jumping=yvelocity），宿主每帧统一刷新，与状态机解耦（PlayerAnimatorComponent.cs:85-90）；
- **瞬时涟漪**（Hit/Landing/flip trigger）：归 FX 事件层，"trigger 进 → exit-time 自治回位"，不进状态类。
推论：帧内 Idle↔run 不构成状态（混合树两端而已，"C# 只在离地/落地这条物理边上做状态转换"）；Exit 无需清动画参数——"每次进入状态都显式指定目标姿态，不存在残留 bool"。

**6. AnimEndTrigger 与"FSM 不挂动画"原则。**
`AnimEndTrigger` 由动画剪辑的 AnimEnd 事件置位，"仅作表现推进（如攻击收招），FSM 的正确性不得依赖它"（PlayerState.cs:21-22）。接线：动画事件 → `PlayerAnimatorComponent.AnimEnd()` → `ActionMachine.Current.EndTrigger()`（:104-105）。

**7. 模块化宿主。**
"Player 只负责组装和生命周期调度，每个模块自包含其数据和逻辑"（Player.cs:7-10）。模块（PlayerLocomotion/PlayerCombat/PlayerThrust）是 `[Serializable]` 普通类，挂在 PlayerModuleControlComponent 字段上（Inspector 可配），经 `Bind(player)` 注入宿主引用（EntityModule 契约：仅 Bind、无自驱 tick）。状态类只持 player 引用，经 `player.ModuleControlComponent.*` 访问模块。

**8. 硬直/冷却统一走 ActionIgnore 掩码。**
攻击锁=`AddIgnore(attackIgnoreDuration, All)`；突刺冷却=`AddIgnore(thrustCooldown, Dash)`（"冷却就是给自己上锁"，PlayerThrust.cs:22-23）；受击硬直=DamageComponent 上 `AddIgnore(hitRepel.length, All)`。

**9. 判定在命令层，状态 Enter 不再自查。**
AttackCommand.CanExecute（AttackCommand.cs:12-18）=动作机空闲 ∧ 落地 ∧ !IsIgnore(Action)（PlayerCombat.cs:28 注释）。同理 Thrust：`StartThrust` **先 ChangeState 成功才 AddIgnore 占冷却**——"避免守卫拒绝时白白吞掉一次突刺"（PlayerThrust.cs:39-44）。

## 二、工作逻辑（怎么运转）

### 每帧驱动时序（注意：玩家走 Update 渲染帧，敌人 AI 走 FixedUpdate 物理帧）

```
Player.Update → AnimatorComponent.RefreshUpdate (:83-102)
  ① anim.SetFloat(xvelocity/yvelocity)      [Blend Tree 连续量，永远刷新]
  ② MotionMachine.Update() → Current.Update()    [先移动]
  ③ ActionMachine.Update()  → Current.Update()   [后动作——"动作完成当帧即可恢复移动"]
  ④ FX 层权重轮询
Player.Start → InitializeStateMachine: Motion.Initialize(Ground) + Action.Initialize(None)
```

### 输入 → 命令 → 状态链（PlayerInputController.cs:37-70）

```
每帧: Locomotion.SetMoveInput(_input.MoveInput)
按键: TryExecute(Jump/Thrust/Attack) → cmd.CanExecute(player) → cmd.Execute(player)
  AttackCommand：动作机==None ∧ IsGrounded ∧ !IsIgnore(Action) → ChangeState(Attack)
  ThrustCommand：Thrust.CanThrust(!IsIgnore(Dash)) → StartThrust（切状态成功才占冷却）
  JumpCommand：Locomotion.CanJump（!IsActionBusy ∧ !IsIgnore(Jump) ∧ RemainingJumps>0
               ——"动作持锁时移动层在 None，跳跃不得将其拉出"）
               → ApplyJump：先设 rb.velocity.y 再请求 MotionMachine 转 Air
```

### AttackState 全生命周期（ActionStates.cs:32-71）

```
Enter:  ZeroVelocity + AddIgnore(cfg.attackIgnoreDuration=0.3s, All)
        + Combat.BeginAttack()（LastAttackTime + ComboEffect → ForceMove(attackForce) 前冲）
Update: 每帧 ZeroVelocity；动画事件 AttackTrigger(出判定帧)→Combat.HitDetect()
        AnimEndTrigger(收招)→ ChangeState(None)
Exit:   BusyFor(cfg.attackRecovery=0.2s) + locomotionComponent.Interrupt()
        [掐掉比动画长的前冲残速——否则"跑步动画但不位移"（:53-55 注释）]
```

### 其余关键状态

- **ThrustState**：Enter → `Thrust.ThrustCore()`：IsThrusting=true + ForceMove(thrustForce) + 协程（重力归零 → 等 thrustForce.length → 恢复）。Update：`!IsThrusting → None`。ThrustCore 设计为"不切状态、不占冷却——处决链直接复用"。
- **DeathState 终态**：进入=`OnDied` 事件 → ActionMachine.ChangeState(Death)（PlayerAnimatorComponent.cs:70/110）。Enter：locomotion.Stop + gravityScale=0。Update：stateTimer 完 → 协程等 deathAnimationDuration(1.5s) → `GameFlowManager.ReloadCurrent()`（走流程管线而非裸 LoadScene）。禁转出但"任意→Death"未禁=死亡打断一切。
- **MotionNoneState 让位锚点**：animStateName=null、**重写 Update 为空**（"让位期间不得驱动"）、不自愈——恢复由宿主联动触发（MotionStates.cs:30-36）。
- **GroundState**：Enter→`ResetJumps()`（姿态交还的一部分）；Update→`!IsGrounded && |vy|>0.01 → Air`（"真实离地"判据——不查速度的话落地残余速度会误判→Landing 双发→涟漪播两遍，:56-60）。
- **AirState**：`IsGrounded && vy<=0.01 → SetTrigger("Landing") + Ground`——"落地是物理判定，不依赖任何动画事件"。
- **MotionState 基类 Update**：xInput 始终刷新（"避免受击硬直期间残留旧值"）+ `!IsIgnore(Move)` 才 ApplyHorizontal。

### 三模块职责（Assets/Modules/）

| 模块 | 职责 | 关键细节 |
|---|---|---|
| PlayerLocomotion | 移动/跳跃/转身策略 | 空中瞬时转身（平台惯例）；地面"速度过零才 Flip"——转身是移动层内的物理过渡不是动作锁；实际减速渐变在 LocomotionComponent.ApplyHorizontal（deceleration=40 MoveTowards 过零） |
| PlayerCombat | 攻击编排 | BeginAttack（时间戳+前冲）/ HitDetect（动画事件调，**伤害取 GAS 的 AttackPower**——数值与行为打通点）/ 连击窗口预留 |
| PlayerThrust | 突刺 | 冷却查 Ignore(Dash)；StartThrust 先切状态再占冷却；ThrustCore 可被处决链复用 |

### Player 宿主杂项

单例 `Player.Instance`（FindObjectOfType 懒加载）；组件缺失 `SetActive(false)` 整对象（FindObjectOfType 会找到"组件禁用但 GO 激活"的实例→每帧 NRE，Player.cs:51-59）；订阅 `TimeManager.OnLocalTimeScaleChanged` → `anim.speed=新倍率; Velocity×ratio`（子弹时间联动，:103-115）。

## 四、坑与约定

1. **新状态必须注册进对应状态机并想清楚守卫**：进互斥组要加进 ForbidAllBetween；Death 类终态用 ForbidAllFrom。
2. **Exit/Enter 里禁止直接 ChangeState**（transitioning 防重入会拒绝）——跨机联动写在宿主的 Transitioned 订阅里。
3. 状态里计时用**纯 float stateTimer**，别 new Timer——"Timer 构造会注册进 TimeManager.Timers 且需显式销毁"（PlayerState.cs:24-26）。
4. 动画事件只做表现推进（AnimEndTrigger/AttackTrigger），状态转换的**正确性**不得依赖动画（漏帧=卡死）；物理边（离地/落地）一律物理判定。
5. 攻击/突刺的"占锁/占冷却"时机：先 ChangeState 成功再 AddIgnore——反过来会白白吞输入。
6. 伤害数值一律取 `healthManageComponent.AttackPower`（GAS），模块里不存攻击力副本。
7. Ground→Air 的判据带速度阈值（|vy|>0.01），改动时保住它，否则落地涟漪双发。

## 五、与相邻模块的边界

- 上游《支撑服务·输入》：命令模式三段式的 Invoker 在 PlayerInputController；对话期屏蔽发生在 InputManager 层。
- 下游《打击盒与动作系统》：ActionStates 决定何时生成判定盒；AddIgnore 的语义（All=锁 / Dash=CD）在那边统一定义。
- 下游《GAS属性系统》：HitDetect 出伤取 AttackPower；OnDied 事件驱动 DeathState。
- 对照《敌人AI》：刻意不复用玩家状态机（40 行直读优于跨系统耦合）——两套 FSM 保留的共性教训只有"终态守卫 + 防重入 + FSM 不挂动画"。
